# Diagram Quality Schema Skill

## Purpose
Provide a formal JSON Schema definition for Phase2 diagram validation reports. This schema documents the exact structure of `diagram-quality-report.json` files generated by the diagram-validator skill and enables automated validation of report format.

## When to Use
- Validating diagram-quality-report.json structure
- Building tools that parse validation reports
- Understanding report format and fields
- Generating documentation from schema
- Integrating validation reports with external systems

## Schema Location

```
rnvs-marketplace/rnvs-plugin/skills/validation-generation/diagram-validator/schemas/diagram-quality-report.schema.json
```

## Schema Overview

The diagram quality report schema defines:
- **Root level**: Feature, phase, timestamp, overall status/score
- **Diagrams section**: Validation results for each diagram
- **Gate results**: Detailed results for all 5 validation gates
- **Recommendations**: Actionable feedback based on validation

## Root Schema Structure

```json
{
  "feature": "NBM",
  "phase": 2,
  "timestamp": "2025-11-05T12:00:00Z",
  "python_version": "3.11.5",
  "plantuml_cli_available": true,
  "diagrams": { ... },
  "overall_status": "COMPLETE",
  "overall_quality_score": 91.5,
  "recommendations": [ ... ]
}
```

### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `feature` | string | Feature name (e.g., "NBM", "PDA") |
| `phase` | integer | Always 2 for diagram validation |
| `timestamp` | string | ISO 8601 timestamp (UTC) |
| `python_version` | string | Python version used (e.g., "3.11.5") |
| `plantuml_cli_available` | boolean | Whether PlantUML CLI was available |
| `diagrams` | object | Validation results (min 1 diagram) |
| `overall_status` | enum | "COMPLETE" or "INCOMPLETE" |
| `overall_quality_score` | number | 0-100 (average across diagrams) |
| `recommendations` | array | Actionable feedback (min 1) |

## Diagram Result Structure

Each diagram in the `diagrams` object has:

```json
{
  "dependencies": {
    "file": "phase2/dependencies.puml",
    "validation_gates": {
      "gate_1_component_coverage": { ... },
      "gate_2_dependency_completeness": { ... },
      "gate_3_syntax_validation": { ... },
      "gate_4_metadata_completeness": { ... },
      "gate_5_renderability": { ... }
    },
    "quality_score": 94.0
  }
}
```

### Diagram Fields

| Field | Type | Description |
|-------|------|-------------|
| `file` | string | Path to .puml file |
| `validation_gates` | object | Results for each gate |
| `quality_score` | number | 0-100 weighted score |

## Validation Gate Schemas

### Gate 1: Component Coverage

```json
{
  "status": "PASSED",
  "components_in_phase1": 4,
  "components_in_diagram": 4,
  "coverage_percentage": 100,
  "missing_components": [],
  "errors": [],
  "warnings": []
}
```

**Threshold**: ≥80% coverage to pass

### Gate 2: Dependency Completeness

```json
{
  "status": "PASSED",
  "dependencies_in_phase1": 287,
  "dependencies_in_diagram": 256,
  "completeness_percentage": 89,
  "missing_dependencies": ["RNBManager->Database"],
  "errors": [],
  "warnings": []
}
```

**Threshold**: ≥80% completeness to pass

### Gate 3: Syntax Validation

```json
{
  "status": "PASSED",
  "tier1_regex": true,
  "tier2_plantuml_cli": true,
  "validation_method": "Tier 1 + Tier 2",
  "syntax_errors": [],
  "errors": [],
  "warnings": []
}
```

**Validation Methods**:
- `"Tier 1 + Tier 2"` - Both validations ran
- `"Tier 1 (PlantUML CLI not available)"` - Only Tier 1

### Gate 4: Metadata Completeness

```json
{
  "status": "PASSED",
  "legend_present": true,
  "notes_present": true,
  "labels_descriptive": true,
  "layout_pragmas": true,
  "errors": [],
  "warnings": []
}
```

**Required Metadata**:
- Legend block
- Contextual notes
- Descriptive labels (not "Component1", "Service2")
- Layout pragmas (`!pragma layout smetana`)

### Gate 5: Renderability & Quality

```json
{
  "status": "PASSED",
  "syntax_complete": true,
  "component_count": 4,
  "complexity_warning": false,
  "renders_successfully": true,
  "errors": [],
  "warnings": []
}
```

**Complexity Thresholds**:
- < 10 components: Low complexity
- 10-15 components: Moderate complexity
- \> 15 components: High complexity (warning)

## Gate Status Values

All gates use the same status enum:

| Status | Meaning |
|--------|---------|
| `PASSED` | Gate criteria met, no issues |
| `FAILED` | Gate criteria not met, blocking |
| `WARNING` | Passed but with warnings to review |

## Quality Score Calculation

The schema enforces quality scores in the 0-100 range. Scores are calculated as weighted averages:

| Gate | Weight |
|------|--------|
| Gate 1: Component Coverage | 25% |
| Gate 2: Dependency Completeness | 25% |
| Gate 3: Syntax Validation | 20% |
| Gate 4: Metadata Completeness | 15% |
| Gate 5: Renderability | 15% |

**Thresholds**:
- **≥85**: Production-ready
- **70-84**: Acceptable but needs improvement
- **<70**: Not ready for Phase3 (overall_status = "INCOMPLETE")

## Overall Status Determination

`overall_status` is set based on:

1. **COMPLETE** if:
   - ALL validation gates have status "PASSED" or "WARNING"
   - Overall quality score ≥ 70

2. **INCOMPLETE** if:
   - ANY validation gate has status "FAILED"
   - Overall quality score < 70

## Recommendations

The `recommendations` array provides actionable feedback:

**For COMPLETE status (quality ≥85)**:
```json
[
  "✅ All validation gates passed",
  "✅ Diagram quality exceeds minimum thresholds",
  "✅ Ready for Phase 3"
]
```

**For COMPLETE status (70 ≤ quality < 85)**:
```json
[
  "⚠️ All gates passed but quality score is below 85",
  "⚠️ Consider improving diagram quality before Phase 3"
]
```

**For INCOMPLETE status**:
```json
[
  "❌ One or more validation gates failed",
  "❌ Review failed gates and regenerate diagrams",
  "❌ Not ready for Phase 3"
]
```

## Validating Reports Against Schema

### Using Python

```python
import json
import jsonschema

# Load schema
with open('schemas/diagram-quality-report.schema.json') as f:
    schema = json.load(f)

# Load report
with open('phase2/diagram-quality-report.json') as f:
    report = json.load(f)

# Validate
try:
    jsonschema.validate(instance=report, schema=schema)
    print("✅ Report is valid")
except jsonschema.ValidationError as e:
    print(f"❌ Validation error: {e.message}")
```

### Using Node.js

```javascript
const Ajv = require('ajv');
const schema = require('./schemas/diagram-quality-report.schema.json');
const report = require('./phase2/diagram-quality-report.json');

const ajv = new Ajv();
const validate = ajv.compile(schema);

if (validate(report)) {
    console.log('✅ Report is valid');
} else {
    console.log('❌ Validation errors:', validate.errors);
}
```

### Using Command Line (with ajv-cli)

```bash
# Install ajv-cli
npm install -g ajv-cli

# Validate report
ajv validate -s schemas/diagram-quality-report.schema.json \
              -d phase2/diagram-quality-report.json
```

## Schema Extensions

The schema uses JSON Schema Draft 07 and includes:

- **Pattern properties**: Diagram names match `^[a-zA-Z0-9_-]+$`
- **Constraints**: `phase` must be exactly 2
- **Format validation**: `timestamp` must be valid ISO 8601
- **Range validation**: Scores must be 0-100, percentages 0-100
- **Required fields**: Enforced at all levels
- **Min/max items**: Recommendations minimum 1 item
- **Enum validation**: Status values restricted to PASSED/FAILED/WARNING

## Common Validation Errors

### Missing Required Fields

**Error**: `'overall_status' is a required property`

**Fix**: Ensure all required root fields are present:
```json
{
  "feature": "...",
  "phase": 2,
  "timestamp": "...",
  "python_version": "...",
  "plantuml_cli_available": true,
  "diagrams": {...},
  "overall_status": "COMPLETE",
  "overall_quality_score": 85.0,
  "recommendations": [...]
}
```

### Invalid Status Value

**Error**: `'COMPLETED' is not one of ['COMPLETE', 'INCOMPLETE']`

**Fix**: Use exact enum values:
- ✅ `"COMPLETE"`
- ✅ `"INCOMPLETE"`
- ❌ `"COMPLETED"`
- ❌ `"complete"`

### Score Out of Range

**Error**: `105 is greater than the maximum of 100`

**Fix**: Ensure scores are in 0-100 range:
```json
{
  "quality_score": 94.5,  // Valid
  "overall_quality_score": 91.0  // Valid
}
```

### Invalid Phase Number

**Error**: `3 was expected to be 2`

**Fix**: Phase must be exactly 2 for diagram validation:
```json
{
  "phase": 2  // Required constant
}
```

## Best Practices

### Report Generation
1. **Always include all required fields** - Don't skip optional gates
2. **Use UTC timestamps** - Consistent timezone for all reports
3. **Limit missing dependency lists** - Schema enforces max 10 items for Gate 2
4. **Provide actionable recommendations** - Include at least 1 recommendation

### Report Consumption
1. **Validate before parsing** - Use schema validation to catch malformed reports
2. **Check overall_status first** - Determines if Phase2 is complete
3. **Review quality_score** - Even COMPLETE may need improvement if <85
4. **Read recommendations** - Provides context for next steps

### Schema Evolution
1. **Maintain backward compatibility** - Add optional fields, don't remove required
2. **Version the schema** - Update `$id` when making breaking changes
3. **Document changes** - Update this SKILL.md with schema modifications

## Troubleshooting

### Schema Validation Fails

**Problem**: Report generated but fails schema validation

**Solution**:
1. Check Python version in validator (3.10+ required)
2. Verify validator script is up-to-date
3. Review validation errors for specific missing/invalid fields
4. Regenerate report with latest validator

### Missing Gate Results

**Problem**: Not all 5 gates present in report

**Solution**:
- Gate 1 requires `--phase1-analysis` parameter
- Gate 2 requires `--phase1-deps` parameter
- Gates 3-5 always run (no dependencies)
- Ensure Phase1 files exist before validation

### Quality Score Doesn't Match Expectations

**Problem**: Manual calculation differs from report

**Solution**:
1. Verify weighted formula (see Quality Score Calculation section)
2. Check gate percentages (Gate 1, Gate 2)
3. Binary gates (3-5) are 100 if PASSED, 0 if FAILED
4. Score is rounded to 1 decimal place

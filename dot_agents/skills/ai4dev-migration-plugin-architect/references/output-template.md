## Section Guidelines

### Executive Summary

- Keep to 5–8 sentences
- State the goal, the chosen approach, and the top 3 decisions
- Link the architecture to the migration plan's goals

### Architecture Overview

- Explain _why_ this style was chosen, not just _what_ it is
- Reference the pattern catalog for deeper detail
- Include a high-level component diagram reference if diagrams were generated

### Component Design

- One subsection per logical component/service
- Always reference business rules by ID (e.g., `BR001`, `BR015`) from analysis.json
- Include API surface — even if preliminary, show intended endpoints or messages
- List both internal and external dependencies

### Data Architecture

- Respect `constraints.unchanged` from plan.json — never propose changes to constrained items
- If schema is unchanged, explicitly state this
- Data migration approach should align with migration sequence in Section 8

### Integration Design

- Map every external system from `constraints.integration.systems`
- Specify how each integration contract is preserved or evolved
- Call out any breaking changes explicitly

### Security Architecture

- Align with user's Q6 answer
- If auth is unchanged, state the preservation strategy
- Include service-to-service auth if microservices or distributed

### Cross-Cutting Concerns

- One subsection per concern selected in Q7
- Include specific technology recommendations
- Tie back to the architectural style (e.g., distributed tracing is critical for microservices)

### Migration Path

- Sequence components from lowest dependency to highest
- Map risks from plan.json `focus_areas`
- Include rollback strategy for each phase

### Decision Log

- Every question from the interactive session becomes a decision entry
- Include options that were _considered but not chosen_ with brief reasoning
- This is the audit trail for the architecture

### Target Diagrams

- Use the same Mermaid syntax conventions from `mermaid-diagrams` skill references
- Diagrams show the **target** state, not current state
- Reference current-state diagrams from `/diagram` if available for contrast
